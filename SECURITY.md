# Security policy

## Supported versions

Security fixes are provided for the latest tagged release and the current
`main` branch. Development snapshots from `develop` are not supported for
production use.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use **Report a
vulnerability** in the Security tab of the GitHub repository so details remain
private until a fix and disclosure plan are ready.

Do not include real private keys, certificates, databases, settings, exported
profiles, public server addresses, or customer data. Use synthetic examples
and redact operational identifiers.

Include the affected version, expected behavior, observed behavior, impact,
and minimal reproduction steps. Receipt should be acknowledged within seven
days. No guaranteed response or remediation deadline is offered.
